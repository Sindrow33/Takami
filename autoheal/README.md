# `:autoheal` — самовосстанавливающийся парсер источников

HTML → Jsoup → извлечение по конфигу → проверка контракта → вердикт →
ремонт селекторов с голосованием, испытательным сроком и откатом.

## Слои

| Пакет | Назначение |
|---|---|
| `core/model` | модель данных, конфиг источника, нормализация ключей |
| `core/parse` | обёртка над Jsoup (`Dom`/`Node`), безопасные селекторы, чтение значений |
| `core/extract` | `StandardExtractor`, лестница селекторов, `ExtractionTrace` |
| `core/validate` | контракт, `Issue`/`Verdict`, `SourceHealth`, `ErrorBudget` |
| `core/heal` | отпечатки узлов, сходство, синтез селекторов, `Healer` |
| `core/store` | JSON-хранилища, ревизии, `SourceRegistry` |
| `core/engine` | `ParseEngine` — порядок разбора; `ParserStatsProvider` — сводка для UI |
| `core/net` | HTTP-клиент, вежливость к хостам, распознавание капч/проверок |

## Как работает самопочинка

1. **Пока всё хорошо** — `SignatureCapture` снимает отпечатки узлов
   (тег, стабильные классы, форма поддерева, окружение, позиция) и
   эталонные значения. Отпечаток нельзя снять в момент поломки: узла
   уже нет, поэтому этот шаг обязателен на каждом успешном разборе.
2. **Валидатор ловит поломку** — не по факту ошибки, а по расхождению с
   историей: пустой список при `lastGoodCount=24`, пропавшее стабильное
   поле, одно и то же значение у всех карточек, использованный фолбэк.
3. **`Healer` предлагает, но не применяет** — ищет узел заново по
   отпечатку или эталонному значению, затем `SelectorSynth` синтезирует
   CSS и проверяет его на живом документе.
4. **Кворум** — предложение должно прийти независимо 3 раза
   (`RevisionManager.QUORUM`), иначе это случайность одной страницы.
5. **Испытательный срок** — 10 прогонов под наблюдением. База сравнения —
   метрики *сломанного* конфига, который ревизия заменяет, а не идеального
   прошлого: иначе рабочая починка с 0.90 откатывалась бы против 1.00.
   Защита по числу элементов при этом работает от здоровой истории.
6. **Откат** — отвергнутый селектор попадает в блоклист на 30 дней;
   при исчерпании бюджета ошибок движок зовёт человека
   (`Outcome.AskUser`), а не чинит бесконечно.

## Проверка

CI: workflow `app`, шаг `Autoheal unit tests`.

```bash
gradle :autoheal:test
```

30 тестов: контракт валидации (`ValidationTest`), слой лечения
(`HealTest`), полный контур с реестром на диске (`EngineLoopTest`),
сводка для UI (`ParserStatsTest`).

Ключевой тест — `EngineLoopTest`: каталог с редизайном, где все классы
заменены на хеши, восстанавливается движком самостоятельно до 24 из 24
элементов.

## Что доделано в этой ветке

- `core/heal/SelectorSynth.kt` — синтез CSS из найденного узла (не было).
- `core/heal/Healer.kt` — оркестрация ремонта и захват отпечатков (не было).
- `core/engine/ParseEngine.kt` — порядок «разбор → проверка → ремонт →
  запись» в одном месте (был размазан по вызывающим).
- `core/net` — вернулся в сборку (был исключён; код писался под OkHttp 3).
- Демо-`main()` заменены на JUnit-тесты; сборка через Gradle вместо `kotlinc`.

### Исправленные дефекты логики

- Поиск по отпечатку не начинался на списках с одинаковыми карточками:
  второй кандидат с тем же баллом считался неоднозначностью, хотя это
  клон того же элемента в соседней карточке (`Match.isCloneTie`).
- Синтезатор подмешивал блок рекомендаций в каталог: одинаковая вёрстка
  различается только ландмарк-предком (`main` против `aside`).
- Ремонт селектора карточки брал ожидаемое число элементов из сломанного
  разбора, где оно равно нулю; теперь берётся из истории.
- Испытательный срок откатывал рабочую починку, сравнивая её с метриками
  до поломки вместо метрик заменяемого сломанного конфига.
