# Точки входа: интеграция `manga-reader` в приложение

Документ для второго исполнителя. Всё, что нужно, чтобы начать без
дополнительных вопросов: где код, где границы, что считается готовым.

## 0. Координаты

| Что | Значение |
|---|---|
| Репозиторий | `Sindrow33/Takami` |
| Рабочая ветка (главная) | `app-shell-v4` — от неё ветвиться, в неё PR |
| Ветка-источник кода | `manga-reader` (независимая история, `git fetch origin manga-reader`) |
| Сборка и проверка | **только GitHub Actions**, workflow `app`. Локально не собираем |
| JDK / Gradle / compileSdk | 17 / 8.11.1 / 35, Kotlin 2.1.0, AGP 8.7.3 |

Ветки репозитория не имеют общей истории. Забирать код из
`manga-reader` в свою ветку так:

```bash
git fetch origin manga-reader
git checkout -b reader-integration app-shell-v4
git read-tree --prefix=reader/ -u FETCH_HEAD   # либо просто скопировать дерево
```

## 1. Что уже есть в `app-shell-v4`

```
:app        оболочка приложения: тема Aurora, онбординг, главная, таббар
:autoheal   автопарсер: разбор источников, валидация, самопочинка
:player     существовавший ранее модуль плеера
:demo       демо-приложение плеера
```

Дизайн-система живёт в `app/src/main/java/dev/takami/app/ui/theme/`:
`Tokens.kt` (цвета, радиусы, motion) и `Theme.kt` (тип-шкала).
**Токены не переизобретать и не дублировать** — импортировать
`dev.takami.app.ui.theme.Aurora`. Если модулю нужен цвет, которого нет
в токенах, это повод обсудить, а не завести локальную константу.

Экраны, которых ещё нет, обозначены в `:app` заглушкой
`ModulePlaceholder` с указанием ветки — это и есть места подключения.
Для читалки это вкладка «Библиотека» в `MainActivity.kt`.

## 2. Граница между нами

Контракт уже написан и заморожен — это `MangaPageSource` в
`:core:model` ветки `manga-reader`:

```kotlin
interface MangaPageSource {
    suspend fun pages(chapterId: String): List<PageRef>
    fun open(page: PageRef): Flow<PageLoad>
    suspend fun nextChapter(chapterId: String): String?
    suspend fun prevChapter(chapterId: String): String?
}
```

- **Инженер-2 — сторона читалки.** Всё, что читает страницы: перенос
  модулей в корневой проект, движок ленты, UI, применение дизайна,
  подключение к `:app`. Реализацию `MangaPageSource` берёте готовую —
  в ветке есть `FolderPageSource` и `CbzPageSource`, их достаточно,
  чтобы читалка заработала на локальных файлах без всякой сети.
- **Инженер — сторона парсера.** Реализация `MangaPageSource` поверх
  `:autoheal` (терминальный слой: извлечение страниц главы с сайта).
  Отдам как отдельный класс, реализующий тот же интерфейс.

Мы не трогаем файлы друг друга. Пересечение ровно одно — см. §4.

## 3. Задача Инженера-2, по шагам

1. **Перенести дерево модулей** из ветки `manga-reader` в
   `app-shell-v4`. Пути модулей сохранить: `:core:model`,
   `:core:network`, `:core:database`, `:reader:engine`, `:reader:ui`,
   `:translate:*`, `:feature:reader`. Они специально написаны так,
   чтобы вставляться в корневой проект без переименований.
2. **Свести Gradle.** У ветки свой `settings.gradle.kts` и
   `gradle/libs.versions.toml`, и по ним **ни разу не запускали
   сборку** — это прямо написано в комментарии их settings-файла.
   Ожидайте, что версии разъедутся с корневым проектом (Kotlin 2.1.0,
   AGP 8.7.3, compileSdk 35) — это основная работа первого дня.
   Плагины объявлять в корневом `build.gradle.kts` через
   `apply false`, как уже сделано для `:app` и `:autoheal`.
3. **Довести до сборки в CI.** Добавить шаг сборки модулей читалки
   в `.github/workflows/app.yml` рядом с существующими.
4. **Дописать `ReaderActivity`/`ReaderViewModel`.** Сейчас
   `ReaderActivity.onCreate` содержит пустой `setContent {}` с
   комментарием, что тут должен композиться `ReaderRoot`. Реальная
   сборка экрана из `WebtoonReaderScreen` и состояния — не сделана.
5. **Применить дизайн.** Читалка сейчас нейтральная; привести к
   Aurora: фон `Aurora.Surface`, акценты, радиусы, motion-кривые.
   Полноэкранный иммерсивный режим в активити уже реализован —
   его сохранить, это требование дизайна читалки.
6. **Подключить к `:app`.** Заменить `ModulePlaceholder` на вкладке
   «Библиотека» на реальный вход: список тайтлов → главы → запуск
   читалки через `MangaReader.open(context, params)`.
7. **Подписаться на события.** `MangaReaderImpl.events` — это
   `SharedFlow`, который надо слушать из process-scoped scope и
   писать прогресс чтения. Читалка сознательно не трогает базу
   прогресса сама, это ответственность приложения.

## 4. Единственное пересечение: `settings.gradle.kts`

Корневые `settings.gradle.kts` и `build.gradle.kts` меняем оба, и
это единственное место конфликтов. Правило: **менять только свои
строки `include(...)`**, не переформатировать файл целиком. При
конфликте побеждает тот, кто мержится вторым, и просто дописывает
свою строку.

## 5. Критерии готовности

- [ ] Workflow `app` зелёный: модули читалки собираются в общем проекте.
- [ ] Юнит-тесты модулей читалки прогоняются в CI и проходят.
- [ ] APK собирается, вкладка «Библиотека» открывает читалку.
- [ ] Читалка открывает главу из локальной папки или CBZ и листается.
- [ ] Экран соответствует токенам Aurora, своих цветовых констант нет.
- [ ] Прогресс чтения долетает до приложения через `ReaderEvent.PageRead`.
- [ ] `README.md` модуля: что сделано, что осознанно не сделано.

## 6. Что читать в первую очередь

В ветке `manga-reader` лежит три документа, и они не формальные:

- `ARCHITECTURE.md` — устройство движка ленты и декодирования.
- `INTEGRATION.md` — контракт с приложением и парсером, обязателен.
- `DECISIONS.md` — принятые решения и их причины.

Отдельно предупреждение из `INTEGRATION.md`, которое легко пропустить:
`ChapterCompleted` прилетает **во время продолжающегося скролла** в
следующую главу — это сигнал «отметить прочитанным», а не событие
навигации. Не вешать на него никакого UI.

## 7. Как связаться

Вопросы по границе, контракту и Gradle — в тред этой задачи.
Если упрётесь в решение, которое меняет контракт `MangaPageSource`, —
это ко мне, менять его в одностороннем порядке нельзя: на нём же
висит парсерная сторона.
