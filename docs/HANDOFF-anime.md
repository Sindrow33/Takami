# Аниме-часть: плеер и свайпы

Модули: `:player` (существовал, до этого в приложение не подключён) и
`:feature:swipes` (новый).

## Точки входа для хоста

```kotlin
// аниме внутри «Библиотеки»
AnimeScreen(contentTree = LibraryRoot(context).selectedTree())
// вкладка «Свайпы» (центральная кнопка)
SwipesScreen()
```

`contentTree: Uri?` — папка, выбранная пользователем через системный диалог;
основной способ. `contentRoot: File?` остался запасным путём на диске и
используется, когда папка не выбрана. Обязательных параметров по-прежнему нет.

- `dev.anime.player.host.AnimeScreen` — обязательных параметров нет.
- `dev.takami.swipes.SwipesScreen` — обязательных параметров нет.

Подключение (одна строка на вкладку) делает владелец `MainActivity.kt`.
Зависимости для `app/build.gradle.kts`:
`implementation(project(":player"))`, `implementation(project(":feature:swipes"))`.

## Что найдено при инвентаризации

1. **Весь `:player` не был подключён** — единственным потребителем был `:demo`.
2. **`PlaybackEnhancer` не инстанцируется нигде**, кроме своих тестов: ASR-субтитры,
   AI-озвучка, ducking и сетевые skip-провайдеры написаны целиком и не вызываются.
   Осознанно не подключаю сейчас: ASR требует `AudioSource` (отдельный декод-пайплайн
   через MediaExtractor/FFmpeg), которого в проекте нет, а озвучка — синтез. Это
   отдельная задача, не «подключить одной строкой».
3. **Падающий тест `AniSkipProviderTest`** — модуля не было в CI, поэтому не видели.
   Ошибка была в самом тесте: он ждал OP первым, а провайдер сортирует по времени
   начала, и рекап (0:00) законно раньше опенинга (0:12).
4. **Реальный баг перекрытия сегментов**: `PlayerScreen` брал `firstOrNull` из
   сегментов, попадающих в позицию. AniSkip отдаёт перекрывающиеся (рекап 0:00–0:30
   и опенинг 0:12–1:42) — кнопка перематывала на 0:30, то есть в середину опенинга,
   и появлялась второй раз. Заменено на `activeSegmentAt` (сегмент с самым дальним
   концом), покрыто тестами.

## Возобновление просмотра

`PlaybackPosition` — чистые функции над числами (порог начала 10 с, порог конца 20 с,
доля просмотра, подпись «остановились на …»), `WatchProgressStore` — только чтение
и запись в SharedPreferences `takami.anime.progress`. Позиция сохраняется каждые ~5 с
по ходу просмотра, а не только на выходе: процесс убивают в фоне.

## Чтение из выбранной папки (`content://`)

`AnimeCatalog.scanTree` обходит дерево через `DocumentFile`. Копирования в кеш нет
и не нужно: Media3 играет `content://` напрямую, а серия — сотни мегабайт на каждый
просмотр (в отличие от страницы манги, которую читалка требует файлом на диске).

Внутри выбранной папки смотрим в подпапку `anime`, а если её нет — в саму папку:
пользователь, указавший сразу свою папку с аниме, иначе видел пустой экран.

Обход каталога вынесен в `Dispatchers.IO`: на content-провайдере это ещё и IPC,
а не только чтение диска.

## Третий найденный дефект: движок играл только сеть

`Media3Engine` собирался с `DefaultMediaSourceFactory(httpFactory)` — то есть
поверх голой HTTP-фабрики. С ней ExoPlayer умеет только `http(s)://`: локальный
файл (`file://`) и документ из выбранной папки (`content://`) не открывались
вообще, независимо от того, что показывает список. Заменено на
`DefaultDataSource.Factory(context, httpFactory)` — источник выбирается по схеме,
а для сети используется та же HTTP-фабрика, поэтому заголовки и таймауты потоков
сохранены.

Это ровно тот же класс дефекта, что и остальные в проекте: код написан целиком и
на реальных данных не выполнялся ни разу — `:demo` проверял только сетевые URL.

## Плеер под Tadami (жесты и панель)

Эталон: `Tadami-Aniyomi-fork`, `ui/player/controls/GestureHandler.kt`.
Вся арифметика — в `ui/PlayerGestures.kt` под JVM-тестами (14 тестов).

Перенесено:
- Зоны экрана 2/5 – 1/5 – 2/5. Ровно половина не годится: центральная пауза
  тогда попадает под палец при любом промахе по краю.
- Двойной тап по краям — перемотка ±10 с с накоплением; тап в обратную сторону
  сбрасывает счёт, а не продолжает его (`+30` → тап влево → `−10`, не `+20`).
- Двойной тап по центру — пауза.
- Вертикальный свайп: слева яркость, справа громкость, с оверлеем и полоской.
  Яркость — свойство окна, поэтому при выходе из плеера возвращается системная,
  иначе выбранная в плеере яркость осталась бы на всём приложении.
- Горизонтальный свайп — перемотка с предпросмотром позиции. Плеер на время
  жеста ставится на паузу: иначе позиция уезжает под пальцем.
- Удержание — 2x, при отпускании возвращается прежняя скорость.
- Верхняя панель: «назад», название серии, переключатель скорости по пресетам.
- Нижняя панель: полоса буфера под слайдером, шаг ±10 с по бокам от play/pause.

Сознательно НЕ перенесено:
- Удержание с горизонтальным слайдом по пресетам скорости и гистерезисом
  (`calculateSpeedPresetStep`): это под mpv, а на телефоне жест конфликтует с
  горизонтальной перемоткой. Вместо него — удержание 2x плюс кнопка скорости.
- Выбор качества и озвучки (`PlaybackSelectionResolver`): выбирать не из чего,
  пока источники не отдают несколько вариантов. Форма готова, включается вместе
  с каталогом.

Побочно убрана кнопка «Назад», висевшая поверх плеера: она не скрывалась вместе
с интерфейсом и перехватывала жест у левого края экрана.

## ИИ-озвучка и ИИ-субтитры (только для скачанного)

Ограничение «только скачанное» — техническое, а не осторожность:
`MediaExtractor.seekTo` по HLS-сегментам означает повторную загрузку каждого
окна, то есть перекачивание серии по кругу. Правило вынесено в
`enhance/EnhancerAvailability` чистой функцией над URL и покрыто тестами, чтобы
решение «показывать кнопку» не разъезжалось с «сработает ли она».

### Что теперь РАБОТАЕТ: озвучка

Не хватало двух реализаций, из-за которых весь слой не мог включиться:
- `SynthesizedAudioPlayer` — интерфейс без реализации. Добавлен
  `MediaPlayerSynthesizedAudio`.
- `TtsProvider` — не было ни одной реализации. Добавлен `AndroidTtsProvider`
  поверх системного TTS.

Почему системный TTS, а не нейросетевой: нейромодель это десятки мегабайт в APK
на язык, а вес сборки уже был блокером релиза (186 МБ до разделения по ABI).
Интерфейс `TtsProvider` не менялся, так что нейродвижок — это отдельная
реализация, а не переделка слоя.

Текст реплик берётся из субтитров рядом с файлом (`.srt` / `.vtt`, тот же
базовый файл) — `subtitle/SubtitleParser`. Ждать распознавание для файла, у
которого субтитры уже лежат, бессмысленно. Поиск сайдкара работает и для
`content://` (через `DocumentFile.parentFile`), и для пути на диске.

Собирает всё `host/EnhancerController`; кнопка «ИИ» в верхней панели плеера,
причина отказа показывается текстом поверх видео. `PlaybackEnhancer.onTick`
вызывается из `AnimeScreen` каждые ~500 мс — именно этого вызова и не было.

### Что НЕ работает и почему: ИИ-субтитры

`audio/MediaExtractorAudioSource` — недостающее звено `AudioSource` — готов:
отдаёт моно-PCM нужной частоты для любого окна локального файла (второй,
независимый от плеера декод, потому что ASR читает вперёд позиции).
Преобразования звука в `audio/PcmTransforms` под тестами.

Не хватает самой модели распознавания (sherpa-onnx / whisper.cpp) — это десятки
мегабайт нативных библиотек, ровно тот вес, который уже вырезали из сборки. Пока
модели нет, `PlaybackEnhancer` создаётся с `asr = null`, и в интерфейсе честно
написано, чего не хватает (`EnhancerController.asrStatus`).

Тонкости, заложенные в пайплайн звука и закрытые тестами:
- Каналы сводятся усреднением, а не «берём левый»: панорамированная реплика
  иначе теряется целиком.
- Окно подгоняется под точную длину (`fitExact`): декодер отдаёт кадрами и в
  границу окна не попадает, а координатор ASR считает окна по времени —
  «сколько получилось» накапливало бы сдвиг таймкодов по ходу серии.
- `SEEK_TO_PREVIOUS_SYNC`, а не `CLOSEST`: без опорного кадра перед окном первые
  миллисекунды выходят мусором.
- Разметка из субтитров вырезается (`<i>`, `{\pos}`) — иначе TTS произносит
  теги вслух.

## Дорожки, субтитры и «следующая серия»

Эталон: Tadami `PlayerViewModel.loadTracks` + `PlayerSheets`.

`track/MediaTrack` — своя модель дорожки, а не `Tracks.Group`: `Tracks.Group`
нельзя инстанцировать в JVM-тесте, значит логика выбора была бы непроверяема.
Слой Media3 сводится к переводу туда-обратно по паре индексов.

`track/TrackSelection` под тестами. Два правила, которые важнее остального:
- Субтитры НЕ включаются, если звук уже на понятном языке — иначе при русской
  озвучке поверх видео висят русские субтитры. Форсированные при этом
  остаются: они переводят надписи, а не речь.
- Коды языков сравниваются с учётом `ru` / `rus` / `ru-RU`: контейнеры пишут
  по-разному, и точное сравнение строк промахивается на половине файлов.

`hasTrackChoice` скрывает кнопку, когда выбирать не из чего: одна дорожка звука
без субтитров означает список из одного пункта, что хуже отсутствия кнопки.

Выключение субтитров — через `setTrackTypeDisabled`, а не снятие override:
снятый override вернул бы автоматический выбор, то есть субтитры включились бы
обратно.

`host/EpisodeQueue` — «следующая серия», под тестами. Предложение требует
известной длительности: при `durationMs == 0` любая позиция формально близка к
концу, и кнопка выскакивала бы на первой секунде, пока файл открывается.

## Аудит «написано и не подключено» в :player

Прогнал весь модуль на потребителей. Итог на текущий момент:

| Что | Состояние |
|---|---|
| `PlaybackEnhancer`, `AudioSource`, `TtsProvider`, `SynthesizedAudioPlayer` | было не подключено — исправлено, см. выше |
| `PlayerEngine.addSubtitleTrack` | **было не вызвано ниоткуда** — исправлено: сайдкар `.srt`/`.vtt` рядом с файлом теперь добавляется явно. Media3 сам его не видит: это отдельный файл, а не дорожка контейнера |
| `AsrCoordinator`, `AsrDiskCache`, `AsrEngine` | не подключены осознанно: нет модели распознавания |
| `AniSkipProvider`, `AniListAwareSkipProvider`, `ChainedSkipProvider` | не подключены осознанно: нужен id тайтла из каталога |
| `SubtitleWriter` | используется только дисковым кешем ASR. Заработает вместе с ASR |
| `Anime4KShaderPreset`, `VideoFilterChain` (в Tadami) | у нас отсутствуют, и не нужны: это шейдеры под mpv |

Правило на будущее для этого модуля: интерфейс без реализации и класс без
потребителя — это не «задел», а невыполняемый код. Проверять `rg` по имени
класса за пределами его собственного файла и тестов.
