# Аниме-часть: плеер и свайпы

Модули: `:player` (существовал, до этого в приложение не подключён) и
`:feature:swipes` (новый).

## Точки входа для хоста

```kotlin
// аниме внутри «Библиотеки»
AnimeScreen(contentTree = LibraryRoot(context).selectedTree())
// вкладка «Свайпы» (центральная кнопка)
SwipesScreen()
```

`contentTree: Uri?` — папка, выбранная пользователем через системный диалог;
основной способ. `contentRoot: File?` остался запасным путём на диске и
используется, когда папка не выбрана. Обязательных параметров по-прежнему нет.

- `dev.anime.player.host.AnimeScreen` — обязательных параметров нет.
- `dev.takami.swipes.SwipesScreen` — обязательных параметров нет.

Подключение (одна строка на вкладку) делает владелец `MainActivity.kt`.
Зависимости для `app/build.gradle.kts`:
`implementation(project(":player"))`, `implementation(project(":feature:swipes"))`.

## Что найдено при инвентаризации

1. **Весь `:player` не был подключён** — единственным потребителем был `:demo`.
2. **`PlaybackEnhancer` не инстанцируется нигде**, кроме своих тестов: ASR-субтитры,
   AI-озвучка, ducking и сетевые skip-провайдеры написаны целиком и не вызываются.
   Осознанно не подключаю сейчас: ASR требует `AudioSource` (отдельный декод-пайплайн
   через MediaExtractor/FFmpeg), которого в проекте нет, а озвучка — синтез. Это
   отдельная задача, не «подключить одной строкой».
3. **Падающий тест `AniSkipProviderTest`** — модуля не было в CI, поэтому не видели.
   Ошибка была в самом тесте: он ждал OP первым, а провайдер сортирует по времени
   начала, и рекап (0:00) законно раньше опенинга (0:12).
4. **Реальный баг перекрытия сегментов**: `PlayerScreen` брал `firstOrNull` из
   сегментов, попадающих в позицию. AniSkip отдаёт перекрывающиеся (рекап 0:00–0:30
   и опенинг 0:12–1:42) — кнопка перематывала на 0:30, то есть в середину опенинга,
   и появлялась второй раз. Заменено на `activeSegmentAt` (сегмент с самым дальним
   концом), покрыто тестами.

## Возобновление просмотра

`PlaybackPosition` — чистые функции над числами (порог начала 10 с, порог конца 20 с,
доля просмотра, подпись «остановились на …»), `WatchProgressStore` — только чтение
и запись в SharedPreferences `takami.anime.progress`. Позиция сохраняется каждые ~5 с
по ходу просмотра, а не только на выходе: процесс убивают в фоне.

## Чтение из выбранной папки (`content://`)

`AnimeCatalog.scanTree` обходит дерево через `DocumentFile`. Копирования в кеш нет
и не нужно: Media3 играет `content://` напрямую, а серия — сотни мегабайт на каждый
просмотр (в отличие от страницы манги, которую читалка требует файлом на диске).

Внутри выбранной папки смотрим в подпапку `anime`, а если её нет — в саму папку:
пользователь, указавший сразу свою папку с аниме, иначе видел пустой экран.

Обход каталога вынесен в `Dispatchers.IO`: на content-провайдере это ещё и IPC,
а не только чтение диска.

## Третий найденный дефект: движок играл только сеть

`Media3Engine` собирался с `DefaultMediaSourceFactory(httpFactory)` — то есть
поверх голой HTTP-фабрики. С ней ExoPlayer умеет только `http(s)://`: локальный
файл (`file://`) и документ из выбранной папки (`content://`) не открывались
вообще, независимо от того, что показывает список. Заменено на
`DefaultDataSource.Factory(context, httpFactory)` — источник выбирается по схеме,
а для сети используется та же HTTP-фабрика, поэтому заголовки и таймауты потоков
сохранены.

Это ровно тот же класс дефекта, что и остальные в проекте: код написан целиком и
на реальных данных не выполнялся ни разу — `:demo` проверял только сетевые URL.

## Плеер под Tadami (жесты и панель)

Эталон: `Tadami-Aniyomi-fork`, `ui/player/controls/GestureHandler.kt`.
Вся арифметика — в `ui/PlayerGestures.kt` под JVM-тестами (14 тестов).

Перенесено:
- Зоны экрана 2/5 – 1/5 – 2/5. Ровно половина не годится: центральная пауза
  тогда попадает под палец при любом промахе по краю.
- Двойной тап по краям — перемотка ±10 с с накоплением; тап в обратную сторону
  сбрасывает счёт, а не продолжает его (`+30` → тап влево → `−10`, не `+20`).
- Двойной тап по центру — пауза.
- Вертикальный свайп: слева яркость, справа громкость, с оверлеем и полоской.
  Яркость — свойство окна, поэтому при выходе из плеера возвращается системная,
  иначе выбранная в плеере яркость осталась бы на всём приложении.
- Горизонтальный свайп — перемотка с предпросмотром позиции. Плеер на время
  жеста ставится на паузу: иначе позиция уезжает под пальцем.
- Удержание — 2x, при отпускании возвращается прежняя скорость.
- Верхняя панель: «назад», название серии, переключатель скорости по пресетам.
- Нижняя панель: полоса буфера под слайдером, шаг ±10 с по бокам от play/pause.

Сознательно НЕ перенесено:
- Удержание с горизонтальным слайдом по пресетам скорости и гистерезисом
  (`calculateSpeedPresetStep`): это под mpv, а на телефоне жест конфликтует с
  горизонтальной перемоткой. Вместо него — удержание 2x плюс кнопка скорости.
- Выбор качества и озвучки (`PlaybackSelectionResolver`): выбирать не из чего,
  пока источники не отдают несколько вариантов. Форма готова, включается вместе
  с каталогом.

Побочно убрана кнопка «Назад», висевшая поверх плеера: она не скрывалась вместе
с интерфейсом и перехватывала жест у левого края экрана.
