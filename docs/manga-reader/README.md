# manga-reader в составе Takami

Что сделано при интеграции ветки `manga-reader` в `app-shell-v4`.

## Сделано

- 12 модулей ветки перенесены в корневой проект без переименований:
  `:core:model`, `:core:network`, `:core:database`, `:reader:engine`,
  `:reader:ui`, `:translate:{api,onnx,ocr,mt,render,core}`,
  `:feature:reader`. Документы ветки лежат в `docs/manga-reader/`.
- Gradle сведён под корневой проект: AGP 8.7.3, Kotlin 2.1.0,
  KSP 2.1.0-1.0.29, compose-bom 2024.12.01, `compileSdk` 35 у всех
  модулей. Плагины объявлены в корневом `build.gradle.kts` через
  `apply false`, в модулях — обычные `id(...)`; каталог версий из ветки
  оставлен как `gradle/libs.versions.toml` и подтянут к этим версиям.
- Появился модуль `:core:design` — токены `Aurora` и `TakamiTheme`
  переехали из `:app`, чтобы читалка использовала ровно ту же
  дизайн-систему, а не копию. Пакет и импорт не изменились
  (`dev.takami.app.ui.theme.Aurora`).
- Написан `ReaderViewModel`: поднимает состояние из `FeedController`,
  держит декодированным окно ±3 страницы, возвращает измеренные высоты в
  контроллер (лента перестаёт прыгать после декодирования) и транслирует
  события в `ReaderEventBus`.
- `ReaderActivity.onCreate` собирает реальный экран: `ReaderRoot` с
  лентой и хромом. Иммерсивный полноэкранный режим сохранён.
- `WebtoonFeedView` доведён до листаемого: drag-скролл, fling через
  `OverScroller`, тап по ленте показывает/прячет хром. Плейсхолдеры и
  фон end-cap перекрашены с белого на `Aurora.Surface`.
- Вкладка «Библиотека» в `:app` — реальный экран: список локальных
  тайтлов → главы → запуск читалки через `MangaReader.open`.
- `TakamiApplication` слушает `MangaReaderImpl.events` в
  process-scoped scope и пишет прогресс в `ReadingProgressStore`.
  `ChapterCompleted` только помечает главу прочитанной и не влияет на UI.
- Тесты `:reader:engine`: бесшовность вёрстки, `FolderPageSource`,
  поведение `FeedController` на границе глав. Собираются в workflow `app`.

## Осознанно не сделано

- **DI-графа нет.** Вместо Hilt/Koin — `ReaderSourceRegistry`: хост
  регистрирует `MangaPageSource` под своим `sourceId`, активити достаёт
  по тому же ключу. Полноценный граф — отдельная задача
  (`INTEGRATION.md` §7), реестр специально маленький, чтобы его не
  пришлось «разбирать» при переходе на DI.
- **Слой перевода отключён от сборки.** `TranslationMode` хранится в
  состоянии и доезжает до вьюхи, но `TranslationOrchestrator` не
  инстанцируется: ему нужны ONNX-модели, ключ облачного MT и Room-граф.
  Поскольку слой не работал, его модули убраны и из графа зависимостей
  APK — они тянули 33 МБ нативных библиотек впустую. Подробности и
  порядок обратного включения: `docs/manga-reader/TRANSLATION-LAYER.md`.
- **Онлайн-источника нет** — по границе задач это сторона парсера. Всё
  локальное работает через `FolderPageSource`/`CbzPageSource`.
- **Хром минимальный**: заголовок главы, счётчик страниц и три чипа
  режима перевода. Слайдера страниц, боттом-шита настроек, редактора
  блоков и paged-режима нет — они перечислены в `INTEGRATION.md` §7 и не
  влияют на бесшовность.
- **`:translate:onnx` без моделей**: бинарные веса в репозиторий не
  кладём, модуль собирается пустым по ассетам.

## Как проверить читалку

Положить главы на устройство:

```
<files>/manga/<Название>/<Глава>/0001.jpg   # папка со страницами
<files>/manga/<Название>/<Глава>.cbz        # или архив
```

Вкладка «Библиотека» → тайтл → глава.
